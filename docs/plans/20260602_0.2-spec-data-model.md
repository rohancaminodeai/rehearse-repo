# SPEC and data model

## Context
Establish the spec-driven development baseline. SPEC.md becomes the source of
truth; acceptance criteria (AC1–AC5) are written before any implementation.
Advances Phase 0 exit criteria (decisions documented).

## Goals
- SPEC.md written with 5 acceptance criteria
- Data model decided: `customers`, `records`
- Auth model decided: single shared link + personal password (= identity)

## Decisions recorded
- Customer auth: password alone identifies the customer; stored as scrypt hash
- Trainer auth: shared `TRAINER_PASSWORD` env; cookie-based
- Customer session: HMAC-signed cookie (`lib/session.ts`)
- Storage: Postgres for data; local `UPLOAD_DIR` volume for images
