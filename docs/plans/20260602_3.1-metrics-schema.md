# Schema DDL additions

## Context
Trainer needs to attach structured metrics (weight, skeletal muscle, body-fat%,
InBody score) and an explicit measurement date to each record. Customers will
need to react to records. Adds the columns and table to `ready()` DDL; no app
logic changes yet. Advances Phase 3 exit criteria (data model ready).

## Goals
- `records` table gains: `weight`, `skeletal_muscle`, `body_fat_pct`, `inbody_score`, `measured_on`
- New `reactions` table with ownership toggle semantics
- `Record` TypeScript type updated
- Existing 12 tests still green (columns are nullable / have defaults)

## Non-Goals
- Trainer form changes (task 3.3)
- Customer view changes (task 3.4)
- Reaction logic (task 4.1)

## Files touched
| File | Change |
|------|--------|
| `lib/db.ts` | Extend `ready()` DDL; update `Record` type |

## Implementation
1. Add 5 columns to `records` DDL (all nullable or with default):
   - `measured_on DATE DEFAULT CURRENT_DATE`
   - `weight NUMERIC`, `skeletal_muscle NUMERIC`, `body_fat_pct NUMERIC` (kg / %)
   - `inbody_score INT`
2. Add `reactions` table:
   - `id SERIAL PRIMARY KEY`
   - `record_id INT NOT NULL REFERENCES records(id)`
   - `emoji TEXT NOT NULL`
   - `created_at TIMESTAMPTZ DEFAULT now()`
   - `UNIQUE(record_id, emoji)`
3. Update `Record` TS type to include new fields (nullable)

- Input validation — not applicable here (enforced in task 3.2)
- Columns nullable so existing records are unaffected
