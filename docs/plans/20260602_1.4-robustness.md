# Robustness fixes

## Context
Code review of the data layer identified 5 correctness/resilience issues. These
were fixed TDD: failing tests written first (red), then implemented (green).

## Issues fixed
| # | Issue | Fix |
|---|-------|-----|
| 1 | Duplicate password → wrong customer's data exposed | `createCustomer` pre-checks with `authenticateCustomer`; throws `DUPLICATE_PASSWORD` |
| 2 | Failed `ready()` caches rejection permanently | `.catch` resets `_ready = null` so next call retries |
| 3 | Idle Postgres client error crashes process | `pool.on('error', ...)` handler added |
| 4 | Malformed `password_hash` row throws in login loop | `verifyPassword` guards `!salt || !hash` case; returns `false` |
| 5 | No server-side upload validation | `lib/upload.ts` created (task 1.3) |

## Summary
- **What changed:** `lib/db.ts` extended; 3 new test cases in `lib/db.test.ts`
- **Outcome:** 12/12 tests green; duplicate-password and malformed-hash edge cases covered
